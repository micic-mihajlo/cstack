### Autopilot full

**You own the verdicts and the queue. One owner prepares each PR. The root verifies and lands only what the user authorized.** Use for "autopilot this queue", "full autopilot", or another explicit request to drive independent PRs through merge.

This playbook includes merging only when the user's request clearly grants merge authority. If the user asked for a plan, state it and stop. If merge authority is absent, run the same loop to merge-ready and report the gate.

1. **Freeze the queue and authority.** Record each item, repository, base, owner, operator-owned items, and the exact terminal action authorized. Operator-owned items never merge through this run. State a checkable program goal. Create a Codex goal only when the user asked for persistent work.
2. **Spawn one owner per independent PR.** Give each Codex worker a dedicated branch or worktree and exclusive file scope. The owner builds, verifies the real artifact, triages automated findings skeptically, runs `$unslop` when installed, applies No comments, refreshes the base, and drives Babysit to merge-ready. The owner keeps a local `decisions.tsv` trail and reports its exact head SHA. Owners never merge, deploy, post comments, or mutate another branch.
3. **Parallelize only independent writers.** Branch independent work directly from the requested trunk. Serialize overlapping ownership. Sequence dependent work as an explicit base chain. Use Graphite only when `gt` exists and the repository already uses it. Otherwise use GitHub base branches and record the chain yourself.
4. **Swarm-verify every merge-ready head.** At the reported SHA, fan out independent lanes through Swarm. Re-run required gates. Exercise the load-bearing behavior through the real Codex terminal, browser, simulator, service, or provider surface described in [Codex runtime](../references/codex-runtime.md). Audit the diff and receipts without trusting the PR body. A verdict without a real behavioral lane is not clean unless the change is provably non-behavioral and that reason is recorded.
5. **Fix forward and re-verify.** Return findings to the owner. Any new head invalidates the verdict. A base refresh also invalidates it unless the patch and relevant runtime behavior are demonstrably unchanged. Pin every verdict to the current head SHA.
6. **Land the verified frontier from the root.** Re-read the live remote head and base immediately before landing. Merge only a contiguous authorized run with clean verdicts. Re-check dependency order. Do not merge by an older SHA. The root performs the external merge action and records the result. Operator-owned items stop at merge-ready.
7. **Keep the program alive through events.** Use agent waits, task waits, terminal polling, the PR watcher, or an explicitly requested heartbeat. Audit owner liveness from real side effects such as commits, pushes, PR state, check state, and stored reports. Never use a long shell sleep. Replace a genuinely stalled owner with a fresh consolidated brief. Do not confuse silence during a known long check with failure.
8. **Stand down immediately.** An operator hold becomes a zero-write order to every owner. Preserve briefs, branches, decision trails, and current SHA state for resumption.

**Reply:** the frozen queue, owner and state per PR, head SHA, verifier verdict, what landed, open operator gates, countersigns, and decision-trail locations.
